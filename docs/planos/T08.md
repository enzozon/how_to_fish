# T08 — Peixe em terra

**Objetivo:** quando o jogador ganha a luta, o servidor cria o peixe (um cubo colorido por espécie) no chão, perto do jogador. O peixe fica "pulando" com impulsos aleatórios. Um `ProximityPrompt` "Pegar" guarda o peixe no inventário.

**Pronto quando:** o peixe cai, pula e pode ser pego.

---

## Arquivos

```
ReplicatedStorage/Shared/
├─ Types.luau                        (editar: FishDef.color)
└─ Config/
   ├─ Fish.luau                      (editar: cor de cada espécie)
   └─ Fishing.luau                   (editar: tamanho, pulos, tempo de vida)
ServerScriptService/Services/
├─ CreatureService.luau              (criar)
└─ FishingService.luau               (editar: onFishCaught chama o CreatureService)
```

Nenhum objeto novo no Studio: o peixe e o prompt são criados por código em tempo de jogo.

---

## Decisões

- **Um serviço novo, o `CreatureService`**, que o GDD 5.1 já prevê para "peixe em terra, IA, vida". Os peixes agressivos do M2 entram nele. O `FishingService` já passa de 400 linhas e fica só com a pesca.
- O `FishingService` chama `CreatureService.SpawnLandedFish(player, fishId, weight)` no `onFishCaught`, que a T07 deixou vazio. Um serviço pode chamar outro; a regra do AGENTS.md só proíbe serviço chamar controller.
- **Só quem pescou pode pegar o peixe.** Evita que outro jogador roube o peixe no co-op. Se o playtest achar que roubar é divertido ("caos em grupo", GDD), basta tirar essa checagem.
- **O peixe é uma Part só** (`Block`), com cor da espécie e tamanho pelo peso. É greybox; a arte vem no M5.
- **O servidor é dono da física do peixe** (`SetNetworkOwner(nil)`), porque os pulos são aplicados pelo servidor.
- **A espécie e o peso ficam só no servidor**, numa tabela `landed[part]`. A Part leva só o `OwnerUserId` e o nome da espécie no prompt, sem o peso. O valor aparece pela inspeção da T09.
- **Tempo de vida:** um peixe não pego some depois de `LANDED_FISH_LIFETIME_SECONDS`, para não acumular Parts no servidor. Os peixes de quem sai do jogo também são removidos.

```luau
LANDED_FISH_BASE_SIZE = 0.8,        -- studs; lado do cubo de 0 kg
LANDED_FISH_SIZE_PER_KG = 0.5,      -- quanto o lado cresce por kg
LANDED_FISH_MAX_SIZE = 3,
LANDED_FISH_SPAWN_DISTANCE = 4,     -- studs à frente do jogador
LANDED_FISH_JUMP_MIN_SECONDS = 0.8, -- intervalo entre pulos
LANDED_FISH_JUMP_MAX_SECONDS = 1.6,
LANDED_FISH_JUMP_UP_SPEED = 18,     -- studs/s para cima em cada pulo
LANDED_FISH_JUMP_SIDE_SPEED = 6,    -- studs/s de lado (direção aleatória)
LANDED_FISH_LIFETIME_SECONDS = 120,
```

## `Services/CreatureService.luau`

Estado: `landed: { [BasePart]: { owner: Player, fishId: string, weight: number } }`.

### `CreatureService.SpawnLandedFish(player, fishId, weight)`
1. Pegue o `HumanoidRootPart`. Se não houver, pare. O peixe se perde, mas é raro: o jogador morreu no exato momento da captura.
2. Crie a Part:
   - `Name = "Peixe"`, `Size` = cubo de lado `min(BASE + PER_KG * weight, MAX)`, `Color = Fish[fishId].color`.
   - `CanCollide = true`, `Anchored = false`, atributo `OwnerUserId`.
   - Posição: `root.Position + horizontal(LookVector) * SPAWN_DISTANCE + (0, 2, 0)`. Ela cai no chão sozinha.
3. Crie o `ProximityPrompt` dentro da Part: `ActionText = "Pegar"`, `ObjectText = Fish[fishId].name`, `HoldDuration = 0`, `MaxActivationDistance = 8`, `RequiresLineOfSight = false`. Conecte o `Triggered` a `onPickup(part, player)`.
4. `part.Parent = Workspace`, `SetNetworkOwner(nil)` e `landed[part] = { ... }`.
5. **Pulos:** rode um `task.spawn` que, enquanto `landed[part]` existir, espera um tempo aleatório entre os limites e aplica `AssemblyLinearVelocity = (dirX * SIDE, UP, dirZ * SIDE)`, com uma direção horizontal aleatória.
6. **Vida:** um `task.delay(LIFETIME, ...)` remove o peixe se ele ainda estiver em `landed`.

### `onPickup(part, player)`
Valide nesta ordem:
1. `landed[part]` existe (não foi pego nem sumiu).
2. `player == entry.owner`.
3. O jogador está vivo e a distância real do `HumanoidRootPart` à Part é no máximo `Survival.PICKUP_MAX_DISTANCE`.
4. `DataService.AddItem(player, { id = fishId, weight = weight })` devolve um uid. Se o inventário estiver cheio, **o peixe fica no chão**.

Se tudo passar: `landed[part] = nil` e `part:Destroy()`.

### `PlayerRemoving`
Destrua todos os peixes cujo `owner` é o jogador que saiu.

## `FishingService` — o que muda
- `require(script.Parent.CreatureService)`.
- `onFishCaught(player, fishId, weight)` passa a chamar `CreatureService.SpawnLandedFish(player, fishId, weight)`.

---

## Segurança

| Entrada | Validação no servidor |
|---|---|
| Prompt do peixe | peixe ainda existe, jogador é o dono, vivo, distância real ≤ `PICKUP_MAX_DISTANCE`, espaço no inventário |

- A espécie e o peso vêm da luta, e o cliente nunca informa nenhum dos dois. O `AddItem` guarda os valores que o servidor sorteou na T06.
- Um peixe só pode ser pego uma vez (`landed[part]` é limpo antes de qualquer `yield`).
- O número de peixes no mundo é limitado pelo tempo de vida e pela saída do jogador.

## Como testar

### 1. O peixe cai e pula
- Pesque até `Caught` com o roteiro da T07 (estratégia dos 60%, pelo cliente).
- Pelo `execute_luau` no Server, ache a Part `Peixe`. Confira o `OwnerUserId`, a cor igual à da espécie e que ela está a uns 4 studs do jogador.
- Leia a posição Y dela algumas vezes em 3 s: ela tem que variar (pulando). Tire uma captura de tela.

### 2. Pegar
- Leve o personagem até o peixe e aperte `E` com `user_keyboard_input` (funcionou na T04).
- A Part tem que sumir.
- Um script temporário publica num atributo do `Workspace` quantos itens de peixe (ids de `Fish`) há no inventário e o peso do último. A contagem tem que subir 1, e o peso tem que estar dentro da faixa da espécie.

### 3. Tempo de vida
Pesque e não pegue o peixe. Depois de cerca de 120 s, a Part tem que sumir. Dá para ir fazendo outras checagens enquanto espera.

### 4. Dono
Com um jogador só não dá para testar outro jogador pegando. Anote no resumo que a checagem de dono foi conferida só no código. No playtest com dois jogadores (T12), confira.

### Limpeza
- Apague os scripts temporários.
- **Salve o place.**

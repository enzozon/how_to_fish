# T10 — Loja

**Objetivo:** um NPC lojista vende Vara de Siri ($3), Salsicha ($5), Soco-inglês ($24) e Faca ($45). O servidor confere o saldo antes de entregar o item.

**Pronto quando:** comprar com dinheiro suficiente entrega o item e desconta o preço; sem dinheiro, nada acontece.

## Decisões

- **Um NPC separado para comprar.** O Vendedor (T09) continua só comprando os peixes do jogador, e o Lojista vende equipamento. Duas janelas simples em vez de uma com abas.
- **O catálogo sai dos configs:** todo item de `Rods`, `Lures` e `Weapons` com `price > 0`, ordenado por preço. Nenhuma lista nova para manter: um item novo no config já aparece na loja. A `mao` (preço 0) fica de fora.
- **O que cada compra entrega:**
  - **Vara:** `SetEquippedRod(id)` e `FishingService.RefreshRodTool(player)`. Não pode comprar a vara que já tem.
  - **Isca:** `AddItem({ id })` e **equipa automaticamente** (`SetEquippedLure`). Ainda não existe tela para escolher a isca, e sem equipar a compra não serviria para nada. Quando as salsichas acabam, a T06 já volta para a Isca de Graça. A T12 avalia se precisa de um seletor.
  - **Arma:** marca `ownedWeapons[id] = true`. O M1 não tem combate (M2), então a arma só fica registrada como comprada. Não pode comprar duas vezes.
- **`PlayerData.ownedWeapons: { [string]: boolean }`**, com o template `{}`. O `Reconcile` preenche o campo nos saves antigos.
- **`DataService.SpendMoney(player, amount): boolean`** faz as mesmas checagens do `AddMoney` (inteiro, maior que 0, finito) e recusa se o saldo não for suficiente. Atualiza o `leaderstats`.
- **`DataService.GiveWeapon(player, weaponId): boolean`** aceita só ids de `Weapons`.
- **Ordem da compra:** primeiro **todas** as validações (item existe, ainda não tem, cabe no inventário, saldo), depois `SpendMoney` e por fim a entrega. Nada disso faz `yield`, então não há como outra requisição entrar no meio. A entrega não falha depois das validações.

## `EconomyService` — acrescentar

### Catálogo (montado no `Start`)
`catalog: { [string]: { kind: "Rod" | "Lure" | "Weapon", name: string, price: number } }`, mais uma lista ordenada por preço para devolver ao cliente.

### `GetShopList.OnServerInvoke(player)`
Valide `allowRequest(player, "GetShopList")`, save carregado e `IsNearShop(player, "Buy")`. Devolva `{ id, name, price, owned }` na ordem do catálogo. `owned` vale `true` para a vara equipada e para as armas em `ownedWeapons`, e `false` para as iscas.

### `BuyItem.OnServerInvoke(player, id)`
Valide nesta ordem e devolva `{ ok = false, reason = "..." }` na primeira falha:
1. `allowRequest(player, "BuyItem")`, save carregado, perto do Lojista.
2. `typeof(id) == "string"` e `catalog[id]` existe.
3. Vara: `data.equippedRod ~= id`. Arma: `not data.ownedWeapons[id]`. Isca: há espaço no inventário.
4. `data.money >= price`. O motivo `"Sem dinheiro"` aparece para o jogador.

Depois: `SpendMoney(player, price)`, entregue o item conforme o tipo e devolva `{ ok = true, money = data.money }`.

Motivos possíveis: `"Longe da loja"`, `"Item inválido"`, `"Já tem"`, `"Inventário cheio"`, `"Sem dinheiro"`.

## Segurança

| Entrada | Validação no servidor |
|---|---|
| `GetShopList()` | intervalo mínimo, save, perto do Lojista |
| `BuyItem(id)` | intervalo mínimo, save, perto do Lojista, id string do catálogo (preço > 0), ainda não tem (vara/arma), cabe no inventário (isca), saldo suficiente |

- **O preço sai do config do servidor.** O cliente manda só o id.
- `SpendMoney` recusa valor inválido e saldo insuficiente. Não tem como o dinheiro ficar negativo.
- Não dá para comprar a `mao` nem ids de outros configs (peixes, comida).

## Como testar

O save de teste está com cerca de $63, com a vara e uma salsicha.

1. **Compras (play):** leve o personagem até o Lojista e aperte `E`. A janela tem que listar Vara de Siri (Comprado), Salsicha, Soco-inglês e Faca. Tire uma captura de tela.
   - **Salsicha:** o dinheiro cai 5, entra uma salsicha no inventário e `equippedLure = "salsicha"`.
   - **Faca:** o dinheiro cai 45, e a faca aparece como "Comprado".
   - **Soco-inglês** (com cerca de $13): "Sem dinheiro", e o dinheiro não muda.
   - **Faca de novo:** "Já tem".
2. **Vara do zero:** um script temporário chama `SetEquippedRod(player, nil)` e `FishingService.RefreshRodTool(player)`. A vara tem que sumir da mochila. Compre a vara na loja: o dinheiro cai 3 e a vara volta para a mochila.
3. **Persistência:** saia e entre de novo. A faca tem que continuar "Comprado".
4. **Recusas (pelo Client):**
   - `BuyItem("faca")` longe do Lojista
   - `BuyItem("mao")`, `BuyItem("caranguejo")`, `BuyItem(123)`
   - `SpendMoney` (pelo script temporário) com -5, 1.5 e um valor maior que o saldo → `false`

### Limpeza

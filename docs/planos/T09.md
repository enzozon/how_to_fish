# T09 — Venda + inspeção (F)

**Objetivo:** um NPC vendedor (cubo com `ProximityPrompt`) abre um menu para vender itens do inventário. A tecla **F** mostra o valor do item que o jogador olha ou segura. O preço é calculado **só no servidor**.

**Pronto quando:** vender aumenta o dinheiro, e o valor mostrado pelo F é igual ao preço pago.

## Decisões

### Fórmula do preço (GDD 2.4)
`preço = round(baseValue × multiplicador de peso × multiplicador de raridade)`, com mínimo de $1.
- **Peso:** `weight / pesoMédio`, onde `pesoMédio = (min + max) / 2` da espécie. Um peixe de peso médio vale o `baseValue`, e um com o dobro do peso médio vale o dobro.
- **Raridade:** `RARITY_PRICE_MULTIPLIER[rarity]` (Comum 1, Incomum 1,5, Raro 2,5, Épico 5).
- **Comida** (marisco): vale o `baseValue`, porque não tem peso nem raridade.
- **Iscas não são vendidas.** Salsicha comprada não volta a virar dinheiro.
- O preço fica em `ServerScriptService/Lib/Pricing.luau`, fora do `ReplicatedStorage`. O cliente não consegue calcular o preço sozinho; sempre pergunta ao servidor. A inspeção (F) e a venda usam **a mesma função**, então os valores sempre batem.

### Menu de venda
- O cliente abre o menu quando dispara o prompt do vendedor. Ele escuta `ProximityPromptService.PromptTriggered` e checa `ShopType == "Sell"` na Part do prompt.
- A lista vem do servidor (`GetSellList`), já com os preços. O cliente só desenha.
- Cada linha tem um botão **Vender**. Há também **Vender tudo** (com 20 mariscos, vender um por um cansa) e **Fechar**.
- Os dois botões usam o mesmo Remote: `SellItems(uids)`, que recebe uma lista de uids.

### Inspeção (F)
- Se o `Mouse.Target` for um peixe em terra (Part `Peixe`), o servidor responde o preço dele. Qualquer jogador pode inspecionar qualquer peixe; só revela o valor.
- Senão, se o jogador segura uma comida (Tool com `FoodId`), o servidor responde o preço dela.
- Senão: "Nada para inspecionar".
- Isso cobre "o item olhado ou segurado" do M1_TAREFAS. Os peixes do inventário aparecem com preço no menu de venda.

### Um serviço novo: `EconomyService`
Ele vai cuidar de venda e compra, como prevê o GDD 5.1. A T10 acrescenta a compra nele.

### Integrações
- `CreatureService.GetLandedFish(part)`: devolve `{ fishId, weight }` ou `nil`. Só leitura, para a inspeção.
- `FoodService.RefreshFoodTools(player)`: fica pública. Vender mariscos tem que atualizar a Tool `Marisco (n)`.

## `Lib/Pricing.luau`

```luau
-- Preço de venda de um item do inventário, ou nil se o item não é vendável.
Pricing.sellPrice(item: Types.ItemData): number?
```
- Se o id estiver em `Fish` e houver `weight`, aplique a fórmula acima.
- Se estiver em `Food`, use o `baseValue`.
- Qualquer outro caso (iscas, id desconhecido) devolve `nil`.
- Arredonde com `math.floor(x + 0.5)` e use `math.max(1, ...)`.

## `Services/EconomyService.luau`

Estado: `lastRequestAt: { [Player]: number }`, limpo no `PlayerRemoving`.

Helpers:
- `allowRequest(player)`: devolve `false` se a chamada anterior foi há menos de `REQUEST_MIN_INTERVAL`. Senão, atualiza o horário e devolve `true`.
- `isNearShop(player, shopType)`: jogador vivo e a menos de `SHOP_MAX_DISTANCE` de alguma Part no `Workspace` com `ShopType == shopType`. Guarde as Parts no `Start`, lendo os filhos do `Workspace` com esse atributo.

### `GetSellList.OnServerInvoke(player)`
- Recuse (devolva `{}`) se falhar o `allowRequest`, se não houver save ou se o jogador não estiver perto do vendedor.
- Devolva uma lista de `{ uid, name, weight?, price }` para cada item vendável, ordenada por nome.
- **O peso vai para o cliente aqui.** O jogador está vendendo e precisa ver o que está vendendo. Na pesca (T07), o peso ficava escondido para a surpresa da captura, não por segurança.

### `SellItems.OnServerInvoke(player, uids)`
Valide:
1. `allowRequest`, save carregado, perto do vendedor.
2. `typeof(uids) == "table"`, com até `MAX_INVENTORY_ITEMS` entradas, e cada entrada é uma `string`. Ignore uids repetidos.

Para cada uid: se o item existe e `Pricing.sellPrice(item)` não é `nil`, chame `RemoveItem`, some o preço num total e conte. No fim:
- chame `AddMoney(player, total)` **uma vez** (se o total for maior que 0);
- chame `FoodService.RefreshFoodTools(player)`;
- devolva `{ sold = n, earned = total, money = data.money }`.

Uids inválidos são ignorados sem erro.

### `InspectValue.OnServerInvoke(player, target)`
1. `allowRequest`.
2. Se `typeof(target) == "Instance"` e `CreatureService.GetLandedFish(target)` devolver algo, responda `{ name, price }` com `Pricing.sellPrice({ id = fishId, weight = weight })`.
3. Senão, se o personagem tiver uma Tool equipada com `FoodId` e houver pelo menos um item desse tipo no inventário, responda o preço da comida.
4. Senão, devolva `nil`.

## `Controllers/EconomyController.luau`

- **Abrir:** `ProximityPromptService.PromptTriggered`. Se `prompt.Parent:GetAttribute("ShopType") == "Sell"`, chame `GetSellList:InvokeServer()` e monte as linhas: clone o `Template`, preencha `NameLabel` (nome + peso com 2 casas, se houver) e `PriceLabel` (`$n`), e conecte o `SellButton` a `SellItems:InvokeServer({ uid })`. Depois de vender, recarregue a lista.
- **Vender tudo:** `SellItems:InvokeServer(todos os uids da lista atual)`.
- **Fechar:** esconde a janela. Feche também se o personagem morrer. O servidor já recusa vendas longe do NPC, então não precisa checar distância no cliente.
- **F:** `UserInputService.InputBegan` com `KeyCode.F` e `gameProcessedEvent == false`. Chame `InspectValue:InvokeServer(mouse.Target)` e mostre `InspectLabel` por 2 s: `"<nome>: $<preço>"` ou `"Nada para inspecionar"`.
- As chamadas a `InvokeServer` ficam dentro de `pcall`: se o servidor der erro, a UI não pode travar.

## Segurança

| Entrada | Validação no servidor |
|---|---|
| `GetSellList()` | intervalo mínimo, save carregado, perto do vendedor |
| `SellItems(uids)` | intervalo mínimo, save, perto do vendedor, tabela de até 100 strings; cada uid precisa existir e ser vendável; preço calculado no servidor |
| `InspectValue(target)` | intervalo mínimo; só responde para peixe em terra registrado ou comida que o jogador tem e segura |

- **O cliente nunca informa preço nem valor.** Ele só manda uids e recebe números para exibir.
- O `AddMoney` é chamado uma vez por venda, com o total calculado no servidor.
- As RemoteFunctions respondem rápido e não fazem `yield`. Um cliente não consegue travar o servidor com elas.

## Como testar

### 1. Preço (script temporário)
- `sellPrice({ id = "marisco" })` → 1.
- `sellPrice({ id = "caranguejo", weight = 0.6 })` (peso médio) → 3.
- `sellPrice({ id = "lagosta", weight = 1.75 })` (peso médio) → 38 (15 × 2,5 = 37,5).
- `sellPrice({ id = "lagosta", weight = 3.5 })` → 75.
- `sellPrice({ id = "salsicha" })` → `nil`.
- `sellPrice({ id = "caranguejo" })` sem peso → `nil`.

### 2. Vender pelo menu (play)
- O mesmo script temporário dá ao jogador 2 mariscos, 1 caranguejo de 0,6 kg e 1 siri de 0,75 kg, e publica `data.money` num atributo do `Workspace`.
- Leve o personagem até o vendedor e aperte `E`. A janela tem que abrir com as linhas certas e os preços certos (tire uma captura de tela).
- Clique no **Vender** do caranguejo com `user_mouse_input`, usando o `instance_path` do botão. O dinheiro tem que subir 3.
- Clique em **Vender tudo**. O dinheiro tem que subir `2×1 + preço do siri`, e a Tool do marisco tem que sumir.

### 3. F
- **Segurando um marisco** (dê mais um pelo script temporário e equipe pelo Client): aperte `F`. O rótulo tem que mostrar "Marisco: $1".
- **Olhando um peixe em terra:** o script temporário chama `CreatureService.SpawnLandedFish(player, "lagosta", 1.75)`. Aponte o mouse para ele (`user_mouse_input` com `instance_path` do peixe) e aperte `F`. O rótulo tem que mostrar "Lagosta: $38". Pegue o peixe (`E`) e venda: o dinheiro tem que subir exatamente 38.

### 4. Recusas (pelo Client)
Em cada caso, o dinheiro não pode mudar:
- `SellItems:InvokeServer({ uidValido })` longe do vendedor.
- `SellItems:InvokeServer("x")`, `SellItems:InvokeServer({ 1, 2 })` e uma tabela com 101 strings.
- `SellItems:InvokeServer({ uid, uid })` (repetido) perto do vendedor vende **uma** vez.
- `SellItems` com o uid de uma salsicha: não vende.
- Dez `InspectValue` seguidos: só o primeiro responde, os outros voltam `nil` pelo intervalo mínimo.

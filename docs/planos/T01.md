## Decisões que valem para os quatro configs

1. **Formato:** dicionário indexado pelo id, `{ [string]: Def }`. Os serviços vão buscar por id (`Fish[id]`), não percorrer lista. Cada def também tem o campo `id`, igual à chave (GDD 5.2), porque ele é útil quando a def circula sozinha.
2. **Ids:** minúsculos, sem acento, com `_`. Exemplos: `caranguejo`, `isca_gratis`, `vara_siri`, `soco_ingles`. Os ids têm que ser **únicos entre todos os configs**, porque o inventário da T02 vai guardar ids de tipos diferentes na mesma lista.
3. **Imutável:** cada def e cada tabela externa passam por `table.freeze`. Nenhum serviço pode alterar config em tempo de jogo por acidente. Para cada tabela, basta um `for` com `table.freeze(def)` e depois `return table.freeze(t)`.
4. **Tipos em `Types.luau`**, seguindo o AGENTS.md. O GDD 5.2 mostra o tipo dentro de `Fish.luau`, mas a regra do AGENTS vale mais. Os configs anotam o retorno, por exemplo `local Fish: { [string]: Types.FishDef } = { ... }`.
5. **Valores são provisórios.** Os números abaixo são um chute coerente com os preços do GDD. O balanceamento de verdade vem na T12. Só não podem ficar números soltos em outros arquivos.

## `Types.luau` — tipos novos

Os tipos novos entram abaixo do `Module` que já existe:

```luau
export type Rarity = "Comum" | "Incomum" | "Raro" | "Épico"

export type FishDef = {
	id: string,
	name: string,
	island: number,
	lureTier: number,          -- tier da isca que atrai esta espécie (Lures.tier)
	rarity: Rarity,
	baseValue: number,         -- $ antes dos multiplicadores de peso/raridade (T09)
	weightRange: { min: number, max: number }, -- kg
	aggressive: boolean,
	health: number?,           -- só peixes agressivos (M2)
	pullStrength: number,      -- 1..10, usado no minijogo (T07)
}

export type LureDef = {
	id: string,
	name: string,
	tier: number,
	island: number,            -- ilha onde é liberada
	price: number,
}

export type RodDef = {
	id: string,
	name: string,
	price: number,
	strength: number,          -- 1..10, reduz o ganho de tensão (T07)
	resistance: number,        -- 1..10, tensão máxima (T07)
}

export type WeaponDef = {
	id: string,
	name: string,
	price: number,
	damage: number,
}
```

**Mudança em relação ao GDD:** no GDD, `weightRange` é `{ number }` (uma lista `{min, max}`). No plano ele vira `{ min: number, max: number }`. Assim o tipo garante os dois valores e o código fica `range.min` em vez de `range[1]`. **Atualize a seção 5.2 do GDD com esse formato.**

**Ficou de fora de propósito (YAGNI):**
- Cooldown e alcance das armas: o combate é no M2.
- Chance de Reluzente: M5.
- Multiplicadores de raridade: a fórmula de preço é da T09, que decide onde eles ficam.

## Objetos no Studio (MCP)

Nenhum. `Config/` vai aparecer no Studio sozinha quando os arquivos entrarem (lembre que pastas vazias não sincronizam).

## Segurança

- Os configs ficam em `ReplicatedStorage`, então o cliente consegue ler tudo, inclusive as espécies por isca. Isso é aceitável: são dados de design, não segredo.
- **Regra para as próximas tarefas:** o cliente pode *ler* o config para mostrar UI, mas o servidor nunca aceita valor do config vindo do cliente. Quando um Remote receber um id (ex.: "comprar `faca`"), o servidor procura esse id no **próprio** config (`Weapons[id]`) e recusa se for `nil`. Preço, dano e valor sempre saem da cópia do servidor.
- O `table.freeze` impede que um serviço altere o config por acidente. No cliente, não protege contra exploit (o cliente pode fazer o que quiser com a cópia dele). Por isso a regra acima.

## Como testar

### 1. Estrutura
Use `search_game_tree` no Edit, com o path `ReplicatedStorage.Shared.Config`. Os quatro ModuleScripts precisam aparecer.

### 2. Tipos
Abra cada arquivo no Studio e confira que a janela **Script Analysis** não mostra erro nem aviso. O MCP não lê essa janela, então essa checagem é manual. Se o editor tiver luau-lsp, dá para usar os diagnósticos dele.

### 3. Checagem dos dados (via MCP)
Rode este trecho com `execute_luau` no datamodel **Edit**. Ele não vira arquivo no repositório. O esperado é `OK` seguido das tabelas impressas, e nenhum `assert` falhando.

```luau
local Config = game:GetService("ReplicatedStorage").Shared.Config
local configs = {
	Fish = require(Config.Fish),
	Lures = require(Config.Lures),
	Rods = require(Config.Rods),
	Weapons = require(Config.Weapons),
}
local rarities = { Comum = true, Incomum = true, Raro = true, ["Épico"] = true }
local lureTiers = {}
for _, lure in configs.Lures do lureTiers[lure.tier] = true end

local seen = {}
for cfgName, cfg in configs do
	assert(table.isfrozen(cfg), cfgName .. " não está congelado")
	for key, def in cfg do
		assert(table.isfrozen(def), key .. " não está congelado")
		assert(def.id == key, key .. ": id diferente da chave")
		assert(not seen[key], key .. ": id repetido entre configs")
		seen[key] = true
		assert(type(def.name) == "string" and def.name ~= "", key .. ": sem nome")
		if def.price ~= nil then assert(def.price >= 0, key .. ": preço negativo") end
	end
end

for id, fish in configs.Fish do
	assert(rarities[fish.rarity], id .. ": raridade inválida")
	assert(lureTiers[fish.lureTier], id .. ": nenhuma isca com esse tier")
	assert(fish.weightRange.min > 0 and fish.weightRange.min <= fish.weightRange.max, id .. ": peso inválido")
	assert(fish.pullStrength >= 1 and fish.pullStrength <= 10, id .. ": pullStrength fora de 1..10")
	assert(fish.baseValue > 0, id .. ": baseValue inválido")
	assert(not fish.aggressive or fish.health ~= nil, id .. ": agressivo sem health")
end

for cfgName, cfg in configs do
	print("==", cfgName)
	for id, def in cfg do print(id, def) end
end
return "OK"
```

Se o `require` devolver uma versão antiga depois de você editar o arquivo (cache do `require` no Edit), rode de novo depois de salvar. Se ainda assim vier antiga, teste com o play mode (datamodel **Server**).

### 4. Play mode
Rode o play mode. O Output deve continuar só com `Servidor iniciado` e `Cliente iniciado`. Os configs não são serviços, então o Loader não pode carregá-los: eles ficam em `Shared/Config`, fora de `Services/` e `Controllers/`.

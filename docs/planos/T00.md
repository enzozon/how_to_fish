### `ReplicatedStorage/Shared/Types.luau` (ModuleScript)
Guarda os tipos compartilhados. Nesta tarefa, só o contrato de módulo:

```luau
export type Module = {
	Init: ((self: any) -> ())?,
	Start: ((self: any) -> ())?,
}
return {}
```

- `Init` e `Start` são **opcionais**: um módulo sem um deles é aceito.
- Por que dois passos: no `Init` o módulo se prepara (lê configs, pega referências de outros módulos, conecta Remotes). No `Start` ele começa a rodar (loops, eventos do jogador). Assim todos já estão prontos quando qualquer um começa a rodar.

### `ReplicatedStorage/Shared/Util/Loader.luau` (ModuleScript)
Uma função usada pelos dois `Main`, para não duplicar código:

```luau
Loader.loadFolder(folder: Instance): { [string]: Types.Module }
```

Faz, nesta ordem:
1. Pega os filhos diretos de `folder` que são `ModuleScript` (ignora o resto). Ordena por `Name`, para a ordem ser sempre a mesma.
2. Faz `require` de cada um. Se falhar, dá `error` com o nome do módulo (ex.: `[Loader] Falha ao carregar HungerService: ...`). Não segue com o jogo pela metade.
3. Chama `:Init()` em todos que têm `Init`, **em sequência**. Erro também para tudo com `error`, informando o nome do módulo.
4. Chama `:Start()` em todos que têm `Start`, cada um com `task.spawn`, para um `Start` que espera (yield) não travar os outros. Um erro aqui aparece no Output com o stack trace normal.
5. Retorna a tabela `{ [nome] = módulo }`. É útil para testes; os módulos pegam uns aos outros com `require` direto.

Não precisa de `WaitForChild` recursivo, nem de cache, nem de registro de dependências. A ordem alfabética basta por enquanto.

### `ServerScriptService/Main.server.luau` (Script)
```
local Loader = require(ReplicatedStorage.Shared.Util.Loader)
Loader.loadFolder(script.Parent.Services)
print("Servidor iniciado")
```
- Use `game:GetService("ReplicatedStorage")`.
- Se a pasta `Services` não existir no Studio (veja o **Risco 1**), use `script.Parent:FindFirstChild("Services")`. Se ela vier `nil`, pule o carregamento e mostre um `warn`, sem erro.

### `StarterPlayerScripts/Main.local.luau` (LocalScript)
Igual ao servidor, mas com `script.Parent.Controllers` e `print("Cliente iniciado")`.
- Use `ReplicatedStorage:WaitForChild("Shared")`, porque o cliente pode rodar antes da replicação terminar. Faça o mesmo para `Util` e `Loader`.

## Riscos

1. **O Script Sync pode não sincronizar pastas vazias.** Se `Services/`, `Controllers/` ou `Config/` não aparecerem no Studio, o `Main` não pode quebrar. Por isso ele usa `FindFirstChild` e mostra um `warn`. Se isso acontecer, anote no resumo da tarefa. As pastas vão aparecer quando o primeiro módulo entrar nelas (T01/T02).
2. **A pasta `Remotes` fica dentro de `ReplicatedStorage`, que também é sincronizada.** Não sei se o Script Sync apaga instâncias que foram criadas no Studio e não existem em disco. Depois de criar `Remotes`, confira que ela continua lá depois de um save e de uma edição qualquer em `Shared/`. Se ela sumir, pare e avise antes de inventar outra solução.
3. **Caminho do cliente:** confira que `StarterPlayerScripts/` em disco vai para `StarterPlayer.StarterPlayerScripts` no Studio, e não para um Folder solto.

## Como testar (pelo MCP)

1. **Estrutura:** use `search_game_tree` no Edit e confira `ServerScriptService.Main` (Script), `ReplicatedStorage.Shared.Util.Loader` e `Types` (ModuleScript), `ReplicatedStorage.Remotes` (Folder) e `StarterPlayer.StarterPlayerScripts.Main` (LocalScript).
2. **Play mode:** rode `start_stop_play` e depois `get_console_output`. O esperado é `Servidor iniciado` e `Cliente iniciado`, sem erro vermelho e sem `warn` (a não ser o do Risco 1, se ele acontecer).
3. **Ordem Init → Start:** crie os arquivos temporários `Services/_TesteA.luau` e `Services/_TesteB.luau`. Cada um imprime `"<nome> Init"` e `"<nome> Start"`, e o B não tem `Start`. Rode o play mode. O esperado é:
   `_TesteA Init`, `_TesteB Init`, `_TesteA Start`, `Servidor iniciado`.
   Depois **apague os dois arquivos**.
4. **Falha clara:** com um módulo temporário que dá `error("x")` no `Init`, o Output deve mostrar `[Loader]` e o nome do módulo. Apague o módulo depois.
5. Pare o play mode e confira que `git status` só mostra os arquivos listados acima.
